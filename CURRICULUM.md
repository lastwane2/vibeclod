# Vibeclod — Curriculum v3

> Зашёл с нулём и идеей. Вышел со знаниями и работающим приложением.

6 миров. 23 уровня. Каждый уровень = 15-30 минут = видимый результат.
Free: L0-L5 (юзер уходит с живым сайтом). Pro: L6-L22 (данные, юзеры, деньги, запуск).

---

## Принципы

1. **Проблема → Действие → Результат.** Никаких лекций. Каждый уровень начинается с "вот что сломано", заканчивается "вот что теперь работает."
2. **Один app, от начала до конца.** Юзер строит ОДНО приложение все 23 уровня. Оно растёт с каждым уровнем.
3. **Реальный процесс.** Всё как в жизни: AI пишет код → ты проверяешь → сломалось → починил → задеплоил. Не "изучи тему, потом применяй."
4. **Boring Stack.** Next.js + Supabase + Stripe + Vercel. Не потому что лучший — потому что AI знает его лучше всего. Меньше багов = быстрее результат.
5. **Без воды.** Контекст — максимум 200 слов перед действием. Юзер пришёл строить, не читать.
6. **Референсы для дизайна.** Везде где визуал (лендинг, pricing, UI) — просить юзера приложить ссылку на сайт-референс или скриншот. AI с референсом делает в 10 раз лучше чем без.
7. **Не учить тому, что AI знает.** SQL, код запросов, HTML-теги — AI знает лучше. Промпты говорят ЧТО делать и ЧТО проверить. КАК — работа AI.

---

## Стек

| Слой | Инструмент | Почему |
|------|------------|--------|
| Фронтенд | Next.js + Tailwind + shadcn/ui | AI обучен на этом, меньше галлюцинаций |
| База данных | Supabase (PostgreSQL) | Визуальный редактор, бесплатный тир, RLS из коробки |
| Авторизация | Supabase Auth | Идёт в комплекте, не надо настраивать отдельно |
| Платежи | Stripe Checkout + webhooks | Стандарт индустрии, тестовый режим |
| Хостинг | Vercel | Деплой из GitHub автоматом, бесплатный тир |
| Email | Resend | Простой API, бесплатный тир |
| Аналитика | PostHog | Бесплатно до 1M событий/мес |
| AI | Claude Code или Cursor | Юзер выбирает. Мы учим паттерны, а не кнопки |

## WORLD 0 — Старт (L0-L1) — FREE

### Level 0: Инструменты

**Время:** 10 мин

**Проблема:** У тебя ничего нет. Нужно настроить инструменты.

**Что делает юзер:**
1. Создать аккаунт GitHub (если нет) — это где хранится код
2. Установить AI-инструмент:
   - Вариант A: Claude Code (терминал, мощнее, сложнее)
   - Вариант B: Cursor (редактор, проще для новичков)
   - Вариант C: Bolt.new / Lovable (браузер, самый простой старт)
3. Создать аккаунт Vercel (через GitHub) — это где будет жить сайт
4. Подключить GitHub-репо к vibeclod

**Что получает:** Все инструменты настроены. Репо подключен.

**Проверка:** GitHub-репо подключён к vibeclod (API check).

**Ключевой момент:** Мы не заставляем конкретный инструмент. Даём 3 варианта по уровню комфорта. Но все дальнейшие промпты работают с любым.

### Level 1: Твоя идея

**Время:** 15 мин

**Проблема:** Если начать строить без плана, AI сделает что-то рандомное. Нужно 15 минут на план.

**Что делает юзер:**

**Шаг 1 — Выбор идеи.** Три варианта:
- **Принёс свою.** "У меня есть идея" → сразу к шагу 2.
- **Нужна помощь.** Vibeclod показывает 5-7 проверенных идей для первого проекта:
  - Трекер задач (to-do с приоритетами)
  - Трекер привычек (streak-based)
  - Дневник / журнал
  - Трекер расходов
  - Закладки / ридинг-лист
  - Трекер тренировок
  - Простой CRM (контакты + заметки)
- **Не знаю что.** Промпт для AI: "Проинтервьюируй меня. Спроси что мне интересно, чем я занимаюсь, какие проблемы решаю каждый день. Потом предложи 3 идеи для приложения."

**Шаг 2 — PRD за 5 минут.** Юзер даёт AI промпт:
```
Я хочу построить [идея]. Помоги мне написать короткий план:
1. Какую проблему это решает?
2. Кто будет этим пользоваться?
3. 3-5 главных фич (MVP, минимум)
4. Что НЕ делаем (чтобы не раздувать)
```
AI генерирует PRD. Юзер читает, поправляет если надо, сохраняет.

**Шаг 3 — CLAUDE.md.** Юзер создаёт файл CLAUDE.md:
```
# [Название проекта]

## Стек
Next.js 14 + Tailwind CSS + Supabase + Vercel

## Что это
[Одно предложение из PRD]

## Правила
- Пиши на TypeScript
- Используй shadcn/ui для компонентов
- Коммить после каждой фичи
- Всё должно работать на мобилке (375px)
```

**Что получает:** PRD + CLAUDE.md. Ясный план, что строим.

**Проверка:** Prompt-блок оценивает качество PRD (конкретность, scope). Build-блок проверяет CLAUDE.md в репо.

## WORLD 1 — С нуля до ссылки (L2-L5) — FREE

### Level 2: AI строит твоё приложение

**Время:** 15 мин

**Проблема:** У тебя есть план. Пора превратить его в код.

**Что делает юзер:**

**Шаг 1 — Найди референс.** Открой сайт, который ВЫГЛЯДИТ так, как ты хочешь чтобы выглядело твоё приложение. Notion, Linear, Todoist, любой. Скопируй ссылку.

**Шаг 2 — Главный промпт.** Берёт свой PRD и даёт AI:
```
Вот мой план приложения:
[вставить PRD]

Референс по дизайну: [ссылка на сайт]. Мне нравится [что именно: цвета, layout, стиль карточек, навигация].

Построй первую версию. Next.js 14 + Tailwind + shadcn/ui.
Пока без базы данных — hardcoded данные для демо.
Должно работать на мобилке.
Начни с главной страницы и одной основной фичи.
```

**Шаг 3 — Посмотреть результат.** AI сгенерил код. Юзер смотрит в браузере (localhost или preview).

**Шаг 4 — Первый коммит.** `git add . && git commit -m "initial version" && git push`

**Что получает:** Рабочая (примерно) первая версия приложения на GitHub.

**Проверка:** GitHub имеет файлы, минимум 1 коммит, app structure (package.json, src/ или app/).

**Ключевой момент:** На этом этапе приложение работает на фейковых данных. Это нормально. Реальные данные — World 2.

### Level 3: Оно в интернете

**Время:** 10 мин

**Проблема:** Твоё приложение живёт только на твоём компьютере. Давай дадим ему адрес в интернете.

**Что делает юзер:**

**Шаг 1 — Подключить Vercel.**
- Зайти на vercel.com → "Add New Project" → Выбрать свой GitHub-репо → Deploy
- Vercel сам поймёт что это Next.js и всё настроит

**Шаг 2 — Подождать 1-2 минуты.** Vercel собирает проект.

**Шаг 3 — Получить ссылку.** `yourproject.vercel.app` — это твой сайт. Он живой. Отправь ссылку другу.

**Шаг 4 — Автодеплой.** Объяснение (30 сек): теперь каждый `git push` = сайт обновляется автоматом. Пушнул код → через минуту сайт обновился.

**Что получает:** Живой URL, который можно отправить кому угодно. Автодеплой настроен.

**Проверка:** hasDeploy = true (Vercel deployment detected).

**Если build сломался:** Vibeclod показывает: "Vercel не смог собрать проект. Вот что делать:
1. Открой Vercel → Deployments → Последний деплой → Logs
2. Скопируй ошибку
3. Вставь в AI: 'Vercel build failed: [ошибка]. Как починить?'
4. Почини, push, Vercel попробует снова автоматом."

### Level 4: Оно сломано

**Время:** 20 мин

**Проблема:** Открой свой сайт на телефоне. Нажми каждую кнопку. Кликни каждую ссылку. Гарантирую — что-то не работает.

**Это самый важный уровень.** Он учит главному навыку вайб-кодера: проверять и чинить.

**Что делает юзер:**

**Шаг 1 — Тест на телефоне.**
- Открой ссылку на телефоне (реальном, не эмуляторе)
- Текст читается? Кнопки нажимаются? Ничего не уехало за экран?
- Запиши всё, что сломано

**Шаг 2 — Тест кнопок и ссылок.**
- Нажми КАЖДУЮ кнопку. Что-то происходит?
- Кликни КАЖДУЮ ссылку. Куда ведёт? 404?
- Заполни КАЖДУЮ форму. Работает?

**Шаг 3 — Консоль браузера.**
- F12 (или Cmd+Option+I на Mac) → Console
- Красные ошибки? Скопируй их.
- Это окно — твой главный инструмент отладки. Привыкай его открывать.

**Шаг 4 — Чини.**
Для каждого бага:
```
У меня проблема:
[описание что не работает]

Ошибка из консоли:
[вставить ошибку]

Это на странице: [какой]
Ожидалось: [что должно было произойти]
```
AI починит. Push. Проверь снова.

**Шаг 5 — Цикл.** Повтори шаги 1-4 пока всё не работает. Это нормально — 3-5 итераций обычное дело.

**Что получает:** Работающий, мобильный сайт без битых кнопок.

**Проверка:** Минимум 3 коммита (показывает итерации). AI-ревью на: responsive, working links/buttons, no obvious broken elements.

**Ключевое правило (учим тут):**
> AI пишет код. Твоя работа — проверить, найти что сломано, и объяснить AI что починить. Это и есть вайб-кодинг. Не "AI делает всё идеально" — а "AI + ты = работающий продукт."

### Level 5: Сохрани свою работу

**Время:** 15 мин

**Проблема:** Ты уже что-то сломал и не смог откатить, правда? Git — это save points для кода.

**Что делает юзер:**

**Шаг 1 — Git основы.** Три команды, которые нужны:
```
git add .                    # Выбрать что сохранить
git commit -m "описание"     # Сохранить
git push                     # Загрузить на GitHub
```
Аналогия: `commit` = сохранение в игре. `push` = бэкап в облако. `revert` = загрузить старое сохранение.

**Шаг 2 — Практика отката.**
- Сломай что-нибудь специально (удали файл, поломай стили)
- Посмотри: `git diff` — что изменилось
- Откатись: `git checkout -- .` — вернуть всё как было
- Или: `git revert HEAD` — отменить последний коммит

**Шаг 3 — .gitignore.**
Объяснение (30 сек): файл `.gitignore` — список того, что НИКОГДА не загружать на GitHub. Самое важное: `.env.local` (там будут пароли от сервисов). AI должен был создать .gitignore, но проверь.

**Шаг 4 — CLAUDE.md v2.**
Обнови CLAUDE.md — добавь то, что уже знаешь о проекте:
```
## Что уже работает
- [главная страница]
- [основная фича]

## Известные проблемы
- [что ещё не сделано]

## Правила
- Делай маленькие шаги. Одна фича за раз.
- После каждого изменения — commit и push.
- Проверяй на мобилке перед коммитом.
```

**Шаг 5 — Рабочий процесс с AI.** Объяснение:
- **Маленькие шаги бьют большие.** "Добавь форму для новой задачи" лучше чем "построй весь функционал задач."
- **Когда AI делает не то:** Не удаляй всё. Скажи: "Это не то. Вот что не так: [конкретно]. Вот что я хочу вместо этого: [конкретно]."
- **Когда застрял в цикле ошибок:** Очисти контекст (начни новый чат / `/clear`), сформулируй задачу заново.

**Что получает:** Git-навыки, обновлённый CLAUDE.md, понимание рабочего процесса.

**Проверка:** .gitignore есть, CLAUDE.md обновлён, минимум 3 коммита с описательными сообщениями, история показывает итерации.

## WORLD 2 — Реальные данные (L6-L9) — PRO

### Level 6: Данные пропадают

**Время:** 20 мин

**Проблема:** Открой своё приложение. Добавь что-нибудь (задачу, запись, что угодно). Обнови страницу. Пропало? Это потому что сейчас данные живут только в браузере. Закрыл — потерял. Нужна база данных.

**Что делает юзер:**

**Шаг 1 — Supabase аккаунт.**
- Зайти на supabase.com → Создать проект
- Скопировать: Project URL и anon key (из Settings → API)

**Шаг 2 — Env vars (пароли к сервисам).**
Создай файл `.env.local` в корне проекта — туда вставь URL и ключ Supabase.
**НИКОГДА не в коде.** Проверь: `.env.local` есть в `.gitignore`? Если нет — добавь.

Создай `.env.example` — то же самое, но без реальных значений. Этот файл МОЖНО коммитить.

**Шаг 3 — Промпт для AI.**
```
Подключи Supabase к моему проекту.
Мне нужна таблица для [описать что хранишь: задачи/записи/привычки/etc.].
Создай схему, подключи клиент, включи RLS с базовой политикой.
Пока просто подключение — CRUD будет в следующем шаге.
```
AI сам создаст правильную таблицу, клиент и RLS. Тут не надо лезть руками.

**Что получает:** Supabase подключён, таблица создана, env vars настроены, .env.example в репо.

**Проверка:** .env.example существует, .gitignore содержит .env, supabase клиент в коде.

### Level 7: Создать, показать, изменить, удалить

**Время:** 25 мин

**Проблема:** База есть, но приложение всё ещё показывает фейковые данные. Давай подключим.

**Что делает юзер:**

**Промпт для AI:**
```
Замени все хардкод данные на реальные из Supabase.
Мне нужно полное CRUD:
- Создание: форма → запись в базу → обновить список → очистить форму
- Чтение: при загрузке страницы показать все записи из базы
- Обновление: клик по записи → редактирование → сохранение
- Удаление: кнопка удаления с подтверждением
Обновляй UI сразу, без перезагрузки страницы.
```

AI знает как писать Supabase-запросы. Твоя работа — ПРОВЕРИТЬ результат.

**Проверка.** Открой приложение:
- Создай 3 записи
- Обнови страницу — они на месте?
- Отредактируй одну
- Удали одну
- Обнови — всё сохранилось?

Если да — git commit + push.

**Что получает:** Приложение с реальными данными. CRUD работает. Данные сохраняются между перезагрузками.

**Проверка:** Минимум 3 коммита, AI-ревью на: реальный Supabase integration (не хардкод), CRUD операции.

### Level 8: Когда всё идёт не так

**Время:** 20 мин

**Проблема:** Открой приложение в новом инкогнито-окне. Что видит новый юзер? Пустой экран? Белую страницу? А если интернет медленный? А если Supabase лежит?

**Три состояния, которые должны быть ВЕЗДЕ:**

**Что делает юзер:**

**Промпт для AI:**
```
Добавь обработку всех состояний:
1. Loading — пока данные грузятся, показывай скелетоны (не спиннер, скелетоны)
2. Error — если запрос сломался, показывай "Что-то пошло не так" (НЕ техническую ошибку)
3. Empty — если записей нет, показывай "Пока пусто. Создай первую!" с кнопкой
4. Валидация — пустая форма не отправляется, слишком длинный текст обрезается
```

**Проверь каждый сценарий сам:**
- Медленная загрузка: Network tab → Slow 3G → перезагрузи. Видишь скелетон?
- Ошибка: временно сломай URL Supabase в .env → обнови. Видишь сообщение об ошибке?
- Пустое: удали все записи. Видишь empty state?
- Невалидный input: отправь пустую форму. Видишь сообщение?

**Что получает:** Приложение обрабатывает все состояния. Никогда не показывает белый экран.

**Проверка:** AI-ревью на: loading states, error handling, empty states, input validation.

### Level 9: BOSS — Приложение с реальными данными

**Время:** 25 мин

**Проблема:** Всё что ты построил в World 2 — работает ли оно вместе? Давай проверим от А до Я.

**Что делает юзер:**

**Полный тест:**
1. Открой приложение на мобилке — выглядит ок?
2. Создай 5 записей — все появились?
3. Отредактируй 2 — изменения сохранились?
4. Удали 1 — пропала? Другие на месте?
5. Обнови страницу — всё сохранилось?
6. Открой в инкогнито — данные загружаются?
7. Отключи WiFi → обнови → ошибка показывается нормально?
8. Удали все записи → empty state показывается?

**Починить всё что сломано.** Это boss level — не проходишь с багами.

**Задеплоить.**
Но подожди — env vars в Vercel!
1. Vercel → Settings → Environment Variables
2. Добавь `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`
3. Redeploy (Deployments → три точки → Redeploy)
4. Проверь: продакшн-ссылка работает? Данные загружаются?

**Что получает:** Задеплоенное приложение с реальной базой данных, все состояния обработаны.

**Проверка:** hasDeploy, минимум 5 коммитов, файлов минимум 5, комплексный AI-ревью: "Это должно работать как настоящее приложение, не как демо."

## WORLD 3 — Пользователи (L10-L13) — PRO

### Level 10: Любой видит всё

**Время:** 25 мин

**Проблема:** Открой своё приложение в двух разных браузерах (например Chrome и Firefox). Видишь одни и те же данные? Это значит: все видят данные всех. Нет аккаунтов, нет приватности. Любой может удалить чужое.

**Что делает юзер:**

**Промпт для AI:**
```
Добавь авторизацию через Supabase Auth:
- Страница /login и /signup
- Кнопка "Выйти" в навигации
- Если не залогинен — редирект на /login
- Показывать email юзера в навигации
```

**Проверить:**
- Открой /login → создай аккаунт → вошёл?
- Навигация показывает email?
- Выйди → редиректит на /login?
- Открой /dashboard напрямую не залогинившись → редиректит?

**Что получает:** Работающая авторизация. Незалогиненные не видят приложение.

**Проверка:** Auth-страницы существуют, protected routes настроены.

### Level 11: Моё и твоё

**Время:** 25 мин

**Проблема:** Залогинься как User A. Создай задачу. Залогинься как User B (в инкогнито). Видишь задачи User A? Значит данные не разделены.

**Что делает юзер:**

**Промпт для AI:**
